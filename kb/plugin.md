# plugin

## How it works now

- `plugin/` is the `peep` Claude Code plugin; each skill is `plugin/skills/<name>/SKILL.md` with step detail in its `references/`. 12 skills; only ticket, packup, tweet and shoot are model-invocable, the rest set `disable-model-invocation` because every invocable description loads into every session.
- Every skill cites `plugin/references/preamble.md` once at the top: read `.peep/setup.md`, apply `skills.off`, and with no setup self-set up (guess as `walk/references/setup.md` step 1, a 5-line read-back, write on yes with `Written by /peep:<name>`, then carry on; "no" or no reply writes nothing). Pack Up and Tweet run without a setup instead.
- `/peep:walk` is optional tour and customising: two batched rounds (repo, then how the owner works), a read-back, then `.peep/setup.md` (F§1) with only non-default preference keys (`qt.round`, `packup.questions`, `shoot.widths`, `skills.off`), a tour (a numbered **Core** block in rhythm order: qt, ticket, shoot, packup, ducks; then an unnumbered **Extras** block, each skill with a "use when" line) and a suggested first step (`/peep:qt` with no open tickets, else `/peep:ducks`).
- Shared formats live once in `plugin/references/formats.md` (F§1 to F§7); skills cite the section instead of restating it.
- The AI hallmark catalogue is `plugin/references/ai-tells.md` (82 entries, slug IDs, P0 to P2 by who notices); its grep rules live in `ai-tells/rules.mjs` with `scan(text)`, and `rules.test.mjs` holds a bad and a good snippet per rule and keeps the md and `RULES` in step. Per-repo exceptions are `.peep/scrub.md` (F§6: `earned` permanent, `debt` may only shrink) plus inline `scrub-ignore: <id> <reason>`.
- `/peep:scrub` (Scrubadubdub) runs `skills/scrub/scripts/scan.mjs`: catalogue grep rules over changed lines since `main` (falls back to `master`, then `HEAD`) plus untracked files, or `--full`; exceptions applied; one finding per ID per file, scored by severity plus the other IDs in that file. Then an eye pass (`references/eye.md`) that always covers spacing and text, on Shoot shots or `inferred` without a `url`. The numbered report phrases alternatives in the repo's own tokens. On the reply (`references/fix.md`) it fixes only the approved numbers, sends design choices to `/peep:sneak`, writes debt on `debt <n>`, and on `wrong <n>` offers an earned line or names a rule bug.
- Every skill's last step (preamble) bumps its line in `.peep/runs` and, while the old count is below 3, ends with its own `Why:` line tied to a habit: think before code, finish before starting, prove it works. The Why text is the only run-count wording left in each `SKILL.md`.
- Walk's round C (`walk/references/northstar.md`) asks for, problem, hook and non-goals in one AskUserQuestion call, shares Walk's one read-back, then writes `.peep/reel.md` (F§5). Comparables (at most 5) are searched only when the owner picks "Look up comparables first" on the Hook question. There is no `/peep:reel`; Ducks' no-north-star line and the widget's arc line point at `/peep:walk`.
- Question Time asks AskUserQuestion rounds while its run count is below 3 (or whenever `qt.round` is set); from the third run it gives the whole frontier as one numbered list answered with "agree all" or named overrides (`qt/references/rounds.md`).
- `/peep:coderot` with no area argument targets the hot spot, the setup area most touched by the last 20 commits' files, and says which; the cap stays 20 mutants.
- Question Time (under Scope) and Ducks (under Watch) read `.peep/reel.md` only to add a `drift: <id> <why>` line for a ticket off the north star or on a non-goal.
- Ducks lists `done` tickets first as one item with a count, and the read-back's **Do** line `close <n> done: <ids>` closes them all on one yes, one `<id>: close` commit each (`leave <ids>` drops some). Stale `doing` comes second: ticket file unchanged for the setup's `stale.days` (default 3, file mtime), asked as finish, park with a reason, or close. The widget's backend worries the repo's peeps on the same rule (`tickets.rs` `Repo.stale`).
- `/peep:sneak` asks Question Time-style design rounds, reads back, builds 2 or 3 self-contained variants in `.peep/sneak/<slug>/{a,b,c}/`, serves them side by side with `skills/sneak/scripts/serve.mjs` (127.0.0.1, random port), and moves the pick to `design/<slug>/`, deleting the rest. It adds `.peep/sneak/` to `.gitignore` itself and never touches the app.
- `/peep:goose` runs `skills/goose/scripts/map.mjs`: ts/js and Rust imports (or `--graphify graphify-out/graph.json`), files grouped by setup areas, written to `.peep/graph/graph.json` (`edges` `[from, to]`) and a standalone `index.html` with `peep.js` inlined from `skills/goose/assets/`. The page is the AV-93 Pixel desktop graph: one card per area on a plank, laid out by `layoutAreas` (needers left of what they need), area links from `areaLinks`, hover tooltip, a pinned panel with needs, used by, peeps and open tweets; an architecture report sits above it. Query instructions sit in `kb/INDEX.md`. A live session's peep stands on each area its Edit and Write calls touched in the last 30 minutes, read from the tail of its transcript (`~/.claude/projects/<cwd with non-alphanumerics as ->/<sessionId>.jsonl`); with none it falls back to its cwd's area or a `repo root` card.
- `map.mjs --report <candidates.json>` puts Ducks' architecture candidates above the map (Ducks level 5, `ducks/references/report.md` holds the JSON schema). Legend, the top pick beside a 96px house peep, then cards. Each card has a peep whose state shows strength (Strong waiting, Worth exploring thinking, Speculative idle), a pattern lesson from `references/patterns.md`, a stuck/working/success comic strip with before and after SVGs, an ELI5 fold with its source, and a "Copy fix brief" button.
- `/peep:bigpeep` is the global `/batch` rebuilt on the repo setup: little peeps follow `work.md` but never stage, commit or set status; Big Peep sets `doing`, reviews the diff, commits one per ticket. A little peep quiet 10 minutes gets one SendMessage status ask (`references/watch.md`), never a stop, and answers by SendMessage to `main`. An in-batch dep that reaches `done` earlier in the run counts as met.
- `/peep:tweet` posts to `.peep/tweets.md` (F§7), never staged or committed; a live ping via SendMessage is only a nudge to read the board. `/peep:ticket` reads the board before building (work.md 1.5) and folds answered tweets into area notes on close (close.md 4).
- `plugin/hooks/tweet-nudge.mjs` is the plugin's `PreToolUse` hook (`Edit|Write|MultiEdit|Bash`). It tells Claude to post a clash tweet when another live session in the repo edited the same file in the last 30 minutes (goose's `editedFiles`), and a stuck tweet (or `/clear` with no peer) after two failures of one tool in a row. It never blocks and fails silent.
- `/peep:shoot` checks a desktop app's webview over CDP (`shoot/references/webview.md`: debug port, `Runtime.evaluate`, the app's own commands, OS screenshots for native chrome) and applies `references/stable.md` before every fact and shot; a verdict that changes on rerun is `flaky`.
- A blocked `/peep:ticket <id>` still parks it on the first direct dep not `closed`, then walks the depends tree depth-first (`ticket/references/work.md`) and names the next step in `owed`: `next: /peep:ticket <dep>` for the first open dep whose own depends are closed, or `/peep:ticket close <dep>` for a `done` one. `doing` deps are skipped; with none unblocked it names the nearest wake.
- `/peep:packup` writes `.peep/handoff.md` (template in `skills/packup/references/note.md`) with `First command: /peep:ducks` when the next step is clear. Ducks reads the note first, checks branch, commit, uncommitted files and named ticket statuses against it (`ducks/references/drift.md`), reads back the drift, and on yes runs the note's `Then` before its other Do lines.
- With nothing loose and no Pack Up note, Ducks asks "How deep?" (`ducks/references/depth.md`). Each level stacks on the one before: 1 means `clear to proceed`; 2 adds hot spots (`git log -20` files per area); 3 adds candidate cards from the deletion test, each naming a pattern, with one top pick and a "which to explore?" question; 4 adds a fresh-context sweep subagent and the goose map; 5 adds the report page. AskUserQuestion takes 4 options, so level 5 is "reply 5". The output always carries `depth: <level>`. With no answer (headless) it is `depth: 1 (unconfirmed)`.
- Ducks never edits code. A picked candidate becomes a drafted ticket on a yes. A rejected one becomes a `Considered, rejected: <what> - <why>` line in the area note's `## Why it's like this` (an ADR only when the reason is hard to reverse), and is skipped on later runs.

## Watch out

- Pattern names on report cards come only from `references/patterns.md` (6 entries, which also feed the learned list). A new pattern needs the owner's yes. Diagram nodes come from `graph.json`, never invented.

- Runs that stop early (switched off, self-setup declined, bad argument) are not counted.
- `skills.off`, self-setup and the run count are stated once in the preamble; never copy them back into a `SKILL.md`.
- A headless live check of a pack skill needs `--add-dir <repo>/plugin` beside `--plugin-dir`, or the child cannot read the preamble and silently skips it. Walk can never be switched off.
- The Why line is the only addition allowed after a skill's fixed output format.
- `.peep/runs` is per machine and not committed; skills mention a missing `.gitignore` entry rather than editing it.
- Stale tickets and drift never block new work.
- Drift never blocks and is never a question. No `.peep/reel.md`, no drift line.
- A new skill adds itself to Walk's Extras block in `walk/references/tour.md` with a use-when line.
- A grep rule's good snippet must hit no rule at all; a false positive is a bug. The scanner always skips the pack's own catalogue and `skills/scrub/fixtures/` (they hit every rule by design); repo reference folders like `design/` are passed as `--skip`.
- Scrubadubdub never writes an earned line (those are the owner's), never stages or commits, and never picks a design choice; Sneak does that. Anything declared in the repo's DESIGN.md is never flagged; this repo's seed earns only the AV-44 shell choices.
- The plugin loads from `plugin/` directly; a changed skill or hook reaches a running session only after `/reload-plugins` or a restart, and `claude plugin update` is a no-op.
- The tweet nudge fires once per file per session, remembered in `<tmpdir>/peep-tweet-nudge/<sessionId>.json`. Running the hook by hand with a real session id spends that nudge; delete the file before a live check.
- A live ping only lands when the peer runs in the same permission mode; otherwise its harness holds the message for approval and the board carries it alone.
- `map.test.mjs` pins the report's place and shape on the graph page: report above `#board`, top pick first, two `<details>` folds, stuck/working/success panels, no `http` URLs (the page works offline). A graph change must keep all five.
- A graph link to any column but the next runs in the gap under the target's row; a straight run would pass behind the cards in between and read as a chain.
- Goose's graphify input works from a directed or undirected build, but graphify's own `cache_root` sets how `source_file` is made relative: build from the repo root or the paths won't match the setup areas. Its callers differ a little from the import map's (it misses `mod x;` links).
- Live checks run by Claude never send keystrokes to a window: prompts have defaults (a trust dialog's is "No, exit"). Child `claude` sessions need every `CLAUDE*` variable cleared.
- "None for now" on a candidate writes nothing; only a rejection with a reason goes in the area note. `claude -p` has no AskUserQuestion, so any Ducks question must have a stated no-answer fallback and an output line that shows which one was taken.
- Drift touching the note's `Then` (ticket already `done`, branch changed) makes Ducks wait rather than run it on yes. Drift never fixes, stages or stashes anything.
- A live check of a skill that reads `.peep/handoff.md` runs in a throwaway worktree with a child `claude`, so the real note stays untouched; only one live check at a time holds the dev widget and its CDP port.

## Why it's like this

- New users learn the reason behind each step, then stop seeing it once the habit is familiar.
- A north star gives a project a reason to finish rather than abandon; it folded into Walk (AV-118) so a new repo gets one in the same sitting as its setup, not as a separate skill.
- Carrying on is a real step in Ducks that catches what changed between sessions, not "do the handoff"; folding Unpack in keeps the pack to one start-of-session command.
- Any skill sets the repo up inline so a new user's first command just works; the full setup questions stay in Walk alone.
